# v6.1 验证记录

日期：2026-11-07。基线：`ec20cab`（v6.0）。这一版改手机和网页端的体验，骰子物理、规则、过场动画都没有改，电脑宽屏的牌桌画面也没变。

## 本次行为

- 牌桌机位（`src/render/framing.js`）：竖屏、手机横屏、平板按界面留出来的地方算机位，视角不再放大。竖屏相机抬高、更俯视，骰盘和两排骰子撑满宽度；横屏用长一点的焦距撑满高度。电脑宽屏（宽高比 1.6 以上、高度 540 以上）还是 `GAME_CAM`。
- 骰子落定后镜头凑近这几颗（`stage.lookAtPoints`），摆回去、再掷时退回来。只在上面这些小屏幕上，开了“减少动态效果”时不动。
- 为了放大骰盘，竖屏时桌角那枚定先手的币出画了（它只是摆设，先手写在记分牌上）。原来的放大视角就是为了把它塞进来。
- 界面：竖屏记分牌压扁（133 → 82 像素高）、操作区贴底；横屏操作区是底部一条，不再盖住骰盘；掷币时工具栏收成一颗；小横屏选对手一排四个；命运之骰在矮屏幕上不重叠；开场页按钮不再被切掉。
- 触屏：点骰子不用点得很准（34 像素内算最近的一颗）；去掉悬停样式粘住、长按菜单、双指缩放、橡皮筋；适配刘海和底部横条（`viewport-fit=cover`）；键盘提示不显示；添加到主屏幕后是全屏。
- 稳定性：手机锁屏回来 WebGL 上下文丢失时，环境反射重新计算（以前金属全黑）；声音被系统打断后下一次点屏幕恢复；等玩家操作时手机半帧率；对局中不自动息屏（支持的浏览器）；微信等腾讯内核里视频不全屏。
- 网页：`play.html` 从 13.6 MB 减到 6.3 MB（模型只留牌桌 5.6 → 0.6 MB，语音 WAV 换 MP3 2.8 → 0.4 MB），电脑也走这个页面，原来要先下 27 MB。视频用到再下载，空闲时先下到缓存（省流量模式下不下）。网慢时视频卡住先重试，等得更久才放弃。
- 去掉一个从没启用却一直占显存的后期效果（GTAO）。
- 电脑：2K、4K 显示器上界面跟着放大（1.25、1.6 倍）。

## 验证

- `test_ui_runtime` 13 项、`test_logic`、`test_framing`（16 种屏幕框得住、骰盘都变大、电脑宽屏不变）、`test_cup`（36 次投掷没有骰子飞出）、`test_clip` 全部通过。改了 3 处测试：竖屏不再要求桌角的币在画面里（新取景的取舍），其余是测试夹具跟着代码补字段。

- WebGL 上下文丢失再恢复：画面回来，钱币金属质感正常，能继续选骰子，没有 error。
- 截图走完整局（开场、菜单、命运之骰、掷币、掷骰、选骰、胜利）：320×568、360×640、390×844、640×360、844×390、768×1024、1024×768、1440×810、2560×1080、500×800。
- Safari 内核（Playwright WebKit，iPhone 配置，放 H.264）完整打完一局；模拟手机（iPhone UA、放不了 AV1、限速 20 Mbps、CPU 降到四分之一）开场 → 待机 → 菜单 → 小动作正常；H.264 备用片、键盘、后台标签页、机器人打完整局、彩蛋都没有 error。

## 没有验证的

- 真 iPhone、真安卓手机：触屏手感、发热、耗电、刘海、微信里的表现都是按规范写的，没有真机。
- Artifact 真实页面（内置浏览器没登录 claude.ai）。
- 别的会话占满显卡时（Chrome 占到 10 GB 以上），测试里出现过过场动画被自动关掉的警告；显卡空闲时没有复现，这一版把网站模式的卡住等待放宽了，但没能在同样条件下验证。
